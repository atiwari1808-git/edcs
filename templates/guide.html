1. ERIDOC folder & documents

Create one ERIDOC project folder named after your JIRA ID (e.g. ASB-10728) and upload all mandatory documents into it before you verify.

  • Folder name must contain the JIRA ID exactly as you type it on the Verify page.
  • Each document filename should start with the JIRA ID, e.g. ASB-10728_TEST_REPORT.pdf.
  • The scanner checks that every mandatory document is present, non-blank, and readable.

Accepted file formats are .pdf (preferred, with selectable text — not scanned images), .docx, .xlsx and .zip — a .zip is fully accepted (its JIRA-ID naming is still checked and its contents validated where feasible; the old "unsupported content" warning is suppressed).

If your tool marks the ERIDOC Folder Path as required, you must paste the folder link (containing locateId=…) or a path starting with /. A wrong or empty link is now reported as an error — it will not silently fall back to a JIRA-name search.

3. Bitbucket repository

For tools that scan code (In-House, Enable, RPA), the repository name must include the JIRA ID.

  • Repo name pattern: <jira-id>_<short-description> — e.g. asb-10728_ran-trx-automation.
  • Paste the full repository URL, e.g. https://bitbucket.internal.ericsson.com/scm/proj/asb-10728_ran-trx-automation.git.
  • The repo must exist, be reachable by EDCS-Gate, and contain code (not empty).

The code scanner flags hardcoded secrets/passwords and IP addresses. Suggested fixes:

  • Secrets/passwords → Move to Database/.env injected at runtime; rotate the exposed value.
  • IP addresses → Move IPs to configuration/database or static sheet; never hardcode.

4. Running a verification

  1. Open Verify from the top navigation.
  2. Select the Tool. Extra fields (Bitbucket link, ERIDOC path) appear only when that tool needs them.
  3. Choose the JIRA Type and Automation Type. Types marked "no meeting needed" only run document verification.
  4. Enter Customer Name, Automation Name and the JIRA ID.
  5. Provide the Bitbucket Link and/or ERIDOC Folder Path if shown.
  6. Click Run Verification. Scanning usually takes 1–5 minutes.
  7. On PASS you can continue to the Scheduler (for meeting-needed types). On FAIL or ERROR, open the report to see exactly what to fix.

6. Understanding your result

  • PASS Every check passed. You'll receive the report by email; meeting-needed types can proceed to schedule the handover call.
  • FAIL A real problem was found (missing/blank document, hardcoded secret or IP, low compliance score). Open the report — each item lists what failed and a suggested fix.
  • ERROR / could not complete The scan itself couldn't finish — usually a wrong ERIDOC path/link, an unreachable or empty Bitbucket repo, or a service outage. Fix the input shown in the message and re-run. An ERROR never counts as a pass, so you can't schedule off an incomplete scan.
Every verification emails you a full PDF report attachment with the per-check breakdown, so you always have a shareable record of what passed or failed and why.
