EDCS-Gate — User Guide

How to prepare your ERIDOC documents and Bitbucket repository, and run a verification successfully.

1. ERIDOC folder & documents

Create one ERIDOC project folder named after your JIRA ID (e.g. ASB-10728) and upload all mandatory documents into it before you verify.

  • The folder name must contain the JIRA ID exactly as typed on the Verify page.
  • Each document filename should start with the JIRA ID, e.g. ASB-10728_TEST_REPORT.pdf.
  • The scanner checks every mandatory document is present, non-blank and readable.

Accepted formats: .pdf (preferred, selectable text), .docx, .xlsx and .zip. A .zip is fully accepted — its JIRA-ID naming is still checked and its contents validated where feasible.

If the tool marks the ERIDOC Folder Path as required, paste the folder link (containing locateId=) or a path starting with /. A wrong or empty link is reported as an error — it will not silently fall back to a JIRA-name search.

3. Bitbucket repository

For code-scanning tools (In-House, Enable, RPA) the repository name must include the JIRA ID.

  • Repo name pattern: <jira-id>_<short-description> — e.g. asb-10728_ran-trx-automation.
  • Paste the full repo URL; it must exist, be reachable, and contain code (not empty).
  • Secrets/passwords → Move to Database/.env injected at runtime; rotate the exposed value.
  • IP addresses → Move IPs to configuration/database or static sheet; never hardcode.

4. Running a verification

  • Open Verify, pick the Tool (extra fields appear only when needed).
  • Choose JIRA Type and Automation Type (doc-only types skip scheduling).
  • Enter Customer Name, Automation Name, JIRA ID, and the Bitbucket / ERIDOC inputs if shown.
  • Click Run Verification (usually 1–5 minutes).
  • On PASS you can schedule the handover (meeting-needed types). On FAIL/ERROR, open the report to see what to fix.

6. Understanding your result

  • PASS — every check passed; you get the report by email and can schedule (meeting-needed types).
  • FAIL — a real problem was found; the report lists what failed and a suggested fix per item.
  • ERROR / could not complete — the scan couldn't finish (wrong ERIDOC path, unreachable/empty repo, outage). Fix the input in the message and re-run. ERROR never counts as a pass.

Every verification emails a full PDF report attachment with the per-check breakdown.
